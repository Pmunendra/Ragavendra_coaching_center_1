Platform Settings

Leaderboard

Controls the student-facing leaderboard shown at Student > Leaderboard.

Commerce — GST

Controls how GST is applied to course purchases. Currency isn't configurable here since the payment gateway (Razorpay India + UPI) only settles in INR - a currency switch wouldn't change what's actually charged, so it isn't offered as a setting.

Inclusive (checked): a ₹999 course stays ₹999 at checkout; the GST portion is shown as a breakdown only.
Exclusive (unchecked): a ₹999 course becomes ₹999 + GST at checkout, so the student pays more than the listed price.
Commerce — Platform / Payment Convenience Fee

An extra fee charged to the student on top of the plan price (shown to them as a separate line at checkout, before GST-inclusive/exclusive handling above). This is our own configurable fee, not a pass-through of whatever Razorpay actually deducts from the merchant account.

Example: a ₹200 plan with a fixed ₹3 fee is billed to the student as ₹203 total. A percentage fee is applied to the post-discount, post-GST amount - never to the original listed price. This is a global setting for now; the same field on each purchase record (platform_fee_amount) keeps the actual fee charged, so per-plan fees can be introduced later without losing this history.
Refunds

Controls the amount pre-filled when an admin refunds a purchase from the Payments page. The admin can still type a different amount for a partial refund.

WhatsApp Chat Button

A floating WhatsApp button shown on every public page. Stays hidden until a number is set below.

India example: 91 followed by the 10-digit number, e.g. 919876543210.
WhatsApp Message Templates

Meta's WhatsApp Cloud API requires a pre-approved template to message a student outside an active support conversation (create/approve these under Meta Business Manager > WhatsApp Manager > Message Templates). Enter the exact approved template name for each purpose - leave blank to skip that template (the app degrades gracefully rather than failing).

Currently wired in: Support Resolved is sent (best-effort - never blocks marking a conversation resolved) when management resolves a WhatsApp conversation. The rest are configured here and ready to use via whatsapp_service.send_template_message(), but nothing else triggers them yet - a proactive marketing/reminder send needs its own explicit opt-in flow per WhatsApp policy, which is out of scope for the support-conversation feature this was built for.
